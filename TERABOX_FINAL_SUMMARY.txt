ARCHITECTURE
================================================================================

Request Flow:
  App Route
    ↓
  TeraboxHybridHandler (Smart routing)
    ├─ Try Direct API (primary)
    │  └─ Terabox Baidu API
    │     • Fast & reliable
    │     • No dependencies
    │     • Full features
    │
    └─ Fallback to WebDAV (if direct fails)
       └─ Alist WebDAV Interface
          • Automatic activation
          • Proven reliable
          • Seamless operation

Error Recovery:
  Operation Fails
    ↓
  Log warning/error
    ↓
  Retry up to 3 times with backoff (1s, 2s, 4s)
    ↓
  Refresh credentials/token
    ↓
  Success → Return result
  Failure → Try WebDAV if available
  Still failing → Return error to client

Auto-Refresh:
  Every 60 minutes:
    → Check if credential expired
    → If yes, refresh from Terabox
    → Update local cache
    → Log completion
    → Continue normal operation

MONITORING & SUPPORT

Health Endpoint:
  URL: http://localhost:5000/api/health/storage
  
  Response Example:

    "healthy": true,
    "method": "direct",
    "quota": {
      "total": 1099511627776,
      "used": 123456789,
      "free": 999054837987,
      "percentage": "11.23"
    }
  }

Log Monitoring:
  • Watch for auto-refresh: grep "Auto-refresh" logs/backend.log
  • Watch for errors: grep "ERROR\|FAIL" logs/backend.log
  • Watch for fallback: grep "switching to WebDAV" logs/backend.log
  • Expected frequency: Auto-refresh every 60 minutes

Alerting:
  Alert if:
    ❌ Health endpoint returns healthy: false
    ❌ "All retry attempts failed" in logs
    ❌ No auto-refresh for >2 hours
  
  Don't alert on:
    ✅ "switching to WebDAV" - Normal fallback
    ✅ "Attempting direct API" - Normal startup
    ✅ "Using Direct API (primary)" - Expected message

Troubleshooting:
  Issue: "No authentication method available"
    → Solution: Set TERABOX_ACCESS_TOKEN in .env

  Issue: "API error 401: Authentication failed"
    → Solution: Token expired - delete cache (rm terabox_token.json)

  Issue: "Direct API failed, switching to WebDAV"
    → This is normal! System auto-recovered. No action needed.

  Issue: Both methods failing
    → Check Terabox service status
    → Verify network connectivity
    → Check rclone configuration
    → Review full error logs
